feat: auto realm routing; fix log-view stutter; GUI realm switcher

Auto routing (now the default): a model available in both realms is served by
whichever account is free instead of being pinned to the selected realm. The
reported symptom was a domestic account sitting at zero requests while every
call went abroad - DeepSeek, GLM and Kimi exist on both sides, and shared
models were always resolved to the current realm. Exclusive models still pin
themselves (gpt-* to intl, minimax-* to cn).

  - detect_model_realm returns "" for a shared model in auto mode, meaning
    "any realm"; resolve_realm layers an explicit choice over that.
  - Realm mode is now three-way: auto / intl / cn, persisted, with intl and cn
    acting as pins. The auto flag follows the choice and is restored on load -
    previously selecting "auto" left the flag off, so routing silently
    disagreed with the selector.
  - CURRENT_REALM defaults to "auto" and AUTO_REALM derives from it, so a
    fresh install is consistent rather than showing "international" while
    behaving as auto.
  - /health reports the real realm (it was the literal "intl", contradicting
    the account domain beside it) and distinguishes a key that is demanded
    from one that merely exists.

UI stutter when opening the Logs tab: the refresh rendered up to 400 lines by
appending HTML one call at a time, so any backlog arrived in a single batch -
measured at 63 ms for a 3000-line burst. It now builds one HTML string and
inserts it once, caps a tick at 200 lines, and drains a backlog on a short
timer instead of stalling. 63 ms -> 13.8 ms for the burst, 1.3 ms steady.

Tests: adds the auto-routing suite (routing through the request path,
including cooldown handling) and the GUI realm suite (selector, persistence,
hints). 14 suites, all green.
